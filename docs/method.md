# 方法说明：为什么长这样

## 1. 核心判断：图谱的价值不在"抽到了多少"，而在"哪一条能回原文"

题面把四个问题排在一起：**抽得准、连得对、对得齐、查得到回得去**。
前三个都是"质量"，最后一个才是"可核验"。而评分里 `结果可核验性` 与 `实际效果` 同权重段，
`使用增益` 还要求用同输入对照证明改善。

所以本 Skill 的设计约束是：

> 允许图**稀疏**，不允许边**站不住**。

一个缺边可以通过再读原文补回来；一条编出来的边会污染所有下游查询，且无法被审阅者区分。
这直接决定了三件事：

- 抽取器**没有线索就不建边**（`pipeline.extract_relations` 里每个 `emit` 都要过 cue 判断）；
- 每条边**必须**带一段逐字 quote + JATS `paragraph_id`，否则不进图；
- 被拒的引文**保留在 `evidence.rejected[]` 里**，而不是删掉——拒绝本身是结论。

## 2. 语义归模型，机械归脚本

这是这套 Skill 的分工，也是它能被 Agent 调用的原因：

| 层 | 由谁做 | 为什么不能换 |
|-|-|-|
| 什么是一个实体、哪句话真的在陈述关系 | 模型（`draft.json`） | 语义判断写成规则会立刻过拟合到某个主题 |
| 引文是否逐字存在、偏移是否正确、关系签名是否合法 | 脚本 | 这是可判定的，模型不该"记得" |

`draft.json` 的接口故意做成"表面形式 + 段落 id + quote"，因为这是模型最擅长产出的东西；
其余全部由脚本生成。模型无法通过"写得很像"绕过校验。

## 3. 三种命中方式，各自记录

`locate_quote` 做三趟匹配：

| `match_kind` | 含义 | 什么时候用得上 |
|-|-|-|
| `exact` | 逐字节命中 | 正常情况 |
| `folded` | 把 `“ ” ’ – —` 折成 ASCII 后命中 | 引文从渲染版复制过来时 |
| `squashed` | 折叠所有空白后命中 | 原文有换行/双空格/NBSP |

三趟都不中就是**没中**，不猜偏移。这一点很关键：宽容匹配如果把"差不多"也算通过，
校验就失去意义了。所以每次命中都记录 `match_kind`，审阅者能看到这条证据有多硬。

## 4. 概念合并 vs 实例合并

跨篇对齐是本题最容易扣分的地方，题面写得很直接：

> 相同通用方法/材料术语不代表两篇使用了相同物理样品、模型实例、数据集或实验条件。

本 Skill 因此把"合并"拆成两级：

- **概念级**：`WS2` 与 `monolayer WS2` 在同类型下归一为同一 `canonical`，节点
  `scope = cross_paper_concept`，`same_instance_across_papers = false`。
  合并依据写进 `alignment.merges[].basis`。
- **实例级**：显式拒绝。`alignment.blocked[]` 里写 `kind: must_not_merge`，
  `level` 取 `instance` / `condition` / `value`：
  - `instance`：概念相同但两篇没给共同样品/批次/仪器设置；
  - `condition`：两篇对同一对象陈述了**不同且明确**的条件（温度、剂量、衬底…）；
  - `value`：**同名的量不能跨篇合并**——数值与条件属于测量它的那篇论文。

指标（metric）永远不跨篇合并。这不是保守，是题面明确禁止："不能把不同论文的条件、样本
和数值结果合成一个结论"。查询 Q3 就专门演示这一点：它会列出两篇各自的指标，
然后明确回答**不能比较**，并写出"需要什么才能比较"。

## 5. 动态读取 output_contract

题面从未列出 `result.json` 的字段名，因为它由每个案例的 `case.json` 给出。
硬编码字段名会直接丢掉"结果完整性 / 结果可核验性"两项。

`kg.resolve_contract` 因此做的是**容错解析**：

1. 依次尝试 `output_contract` / `required_outputs` / `expected_outputs` / `required_fields`
   等键名，再下探一层 `task` / `spec` / `requirements` / `meta`；
2. 值可以是字段名列表、`字段 → 说明` 的映射、或带 `name`/`field` 的对象数组；
3. 支持 `graph.nodes` 这种点号路径；
4. 解析不到就退回文档化的默认字段集，并在 `contract.source = "fallback"` 里**写明**。

"退回了 fallback" 这件事必须出现在结果里，否则审阅者会以为是平台真的只要这些字段。

## 6. 两套检查，故意不共用代码

构建期跑 QC-01…QC-09；构建后跑 `validate_result.py` 的 V00…V17。
后者**重新打开语料**、重新定位每条引文、重新数 id。

一套自证不算证明。V12 是这套设计里最重要的一条：

> `status=success` ⇒ 被拒引文为 0 且未校验边为 0

它不允许"证据没落地却宣布成功"。这也是同输入对照里 baseline 失败的地方：
一个没有校验环节的流程无法知道自己的引文没落地，因此必然声明成功，而 V12 会当场抓住它。

## 7. 同输入对照怎么做的

`scripts/compare.py` 在同一份语料上跑两个模式，差异来自**能力**而不是提示词：

| 能力 | skill | baseline |
|-|-|-|
| 引文逐字校验 + 字符偏移 | 有 | 无（`match_kind = unverified`） |
| 别名/缩写归一 | 有（只用语料里定义过的缩写） | 无（按表面字符串分组） |
| 概念/实例分层与拒绝 | 有 | 无 |
| 指标跨篇隔离 | 有 | 无 |
| `output_contract` 解析 | 有 | 无（仅跑结构） |
| 查询工作流 | 4 个真实查询 | 无 |

外加两个探针：

- **E2 篡改**：故意改掉一条引文里的一个数字。skill 拒绝并把状态压到 `refused`；
  baseline 原样接受并报告 `success`。
- **E3 重跑**：同一输入跑两次，id 与计数完全一致——图谱可重放，不是一次性产物。

实测数字见 `evidence/compare.json` 与 `docs/reproduce.md`。

## 8. 已知取舍

- **稀疏**：规则抽取器只在有线索时建边，所以边数远少于节点数。这是有意的；
  真正的召回提升应该来自 agent 写 `draft.json`，而不是放宽规则。
- **不做同义词推断**：只用语料自己写下的缩写定义（`ABBR (full name)` / `full name (ABBR)`）。
  没有外部本体，因为外部本体恰恰是"凭常识补全"的来源。
- **不解析图**：图表定位支持到 caption 文本；像素级内容不在语料里，也不去推断。
- **不比较跨篇数值**：即使两个量同名，也不给"更高/更低"的结论。原因见 §4。
