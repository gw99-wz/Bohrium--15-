# 阅读15｜文献知识图谱构建 — 赛题精读笔记

> 本文件是对平台下发 `bohr-product-task/task.md`（Challenge ID `product-arena-10-760d1a0b`）
> 的逐条提炼，只记录**题面实际写了什么**，不掺入推测。凡属我方推断的，标 `【推断】`。
> 引用位置用 `task.md:L行号` 表示。

## 0. 一句话

做一个**可被 Agent 调用的 Skill**，把一批真实论文转成**带证据的节点与边**，并且**能被查询、
能回到原文**。平台用 3 个固定案例、对照"不加载 Skill 的基础 Agent"来评。

交付物是 Skill 本体（`SKILL.md` + 脚本/资源），**不是**预制答案（`task.md:L5`、`L51-52`）。

## 1. 运行契约（Harbor）

| 项 | 要求 | 出处 |
|-|-|-|
| 提交位置 | `/app/submission/SKILL.md` + 必需文本资源，YAML frontmatter 含 `name`/`description` | `L75` |
| 安装位置 | 评测方装到 `/skills/weekly-skill` | `L75` |
| 输入 | `/input/case.json` + `task.md`；材料按题目给定，**PDF 不给预抽好的答案层** | `L77` |
| 工作目录 | `/app/work`；最终结果与可编辑产物放 `/app/output` | `L77` |
| 必交结果 | `result.json`，**含 output_contract 的全部字段 + `case_id`** | `L77` |
| 预算 | 64 次模型请求 / 900 秒 / 单次回复 16384 tokens（含推理） | `L79` |
| 资源上限 | ≤50 个 UTF-8 文本文件，单文件 ≤500KB，合计 ≤2MB，禁止 symlink | `L79` |
| 运行规模 | 3 个案例 × 3 次重复 × 2 条件（基础 Agent / Skill Agent） | `L79` |

诚实性硬要求（`L77`）：状态、来源、不确定性、变更记录都要如实；部分结果必须自述边界；
**不得编造缺失的软件状态或科学数据**。`task.md:L81` 再强调一次：实际输入文件和原论文是事实依据，
**不得依据错误的领域标签补造数据**。

## 2. 输入材料 —— 最容易踩的地方（`L84` 输入修订）

题面在通用模板之后追加了一段**针对本题的输入修订**，它改写了"两篇论文"的定义：

- 现在是**两篇独立、真实、许可可再分发**的论文文本；**不是**同一篇论文的 JSON + Markdown 两个格式。
- `corpus-manifest.json`：逐篇记录 **DOI、作者、来源哈希、许可证**。
- `material.json`：两篇**正文段落的汇总索引**。
- `primary-material.json`：原论文（第一篇）；`secondary-material.json`：新增论文（第二篇）。
  两者都能回溯到**各自**的原文。
- **根级 DOI / title / authors 属于第一篇，不得套到第二篇**（`L84`）。
- 定位是**组织方给的 JATS 段落 ID，不是实际 PDF 页码**；本包**没有 PDF 页码**，
  **不得把自建的"第 1 页"称作原 PDF 页**（`L88`）。
- 正文行内公式/上下标被**线性化**；核对请用原始 `secondary-publisher.xml`。
- **不提供**图像像素、补充附件、底层临床或实验数据 → **不允许推断其中数值**（`L88`）。
- 只有"同一篇论文有多种文件格式"**不算**跨篇证据（`L86`）。

## 3. 图谱要包含的核心要素

### 3.1 实体（`L18`、`L22`）

| 实体类型 | 题面措辞 | 硬性要求 |
|-|-|-|
| 研究者 researcher | 研究者 | 真实出现在论文中 |
| 材料 material | 材料 | 真实出现，保留原文表述 |
| 方法 method | 方法 | 真实出现 |
| 任务 task | 任务 | 真实出现 |
| 指标 metric | 指标 | 真实出现 |
| 结论 conclusion | 结论 | 真实出现 |

除类型之外，实体还必须满足：

1. **抽得准**：实体必须对应论文里**真实出现**的科研对象，不能是模型凭常识补全的概念（`L18`）。
2. **保留原文位置与表述原文**（`L22`）。
3. **区分作者自述与他人转述**（`L22`）。
4. 每个**实质节点**要有独立论文的 `source_id`、`paragraph_id` 和**原文短引**（`L88`）。

### 3.2 关系（`L18`、`L22`、`L86`）

- 只建立**有证据支持**的关系（`L22`）。
- 必须明确：**关系类型**、**方向**、**适用条件**（`L22`）。
- 题面举例的关系类型：**使用 uses、比较 compares、优于 outperforms、支持 supports、矛盾 contradicts**
  （`L22`，用"例如"引出 → 是示例集合，非封闭词表 `【推断】`；但我方应自建受控词表并在文档中说明扩展方式）。
- 禁止：把**共现**、**综述转述**、**推测**当成直接证据（`L18`）。
- **连得对**的判据：关系类型、方向、适用条件是否与原文一致（`L18`）。
- 每条边同样要 `source_id` + `paragraph_id` + 原文短引（`L88`），并**标注证据强度**（`L22`）。

### 3.3 跨篇对齐（`L18`、`L22`、`L86`）

要处理：别名、缩写、大小写、全称/简称、**同名实体冲突**。

- 给出**合并依据**；既不产生重复节点，也不把不同对象**错误合并**（`L22`）。
- **记录两类候选**：可以合并的候选（附依据）与**不得合并**的冲突/不同对象（`L86`）。
- **不能强迫每个别名都合并**（`L86`）。
- **不能**把不同论文的条件、样本、数值结果**合成一个结论**（`L86`）。
- **相同通用方法/材料术语 ≠ 两篇用了相同物理样品/模型实例/数据集/实验条件**（`L86`）——
  这是本题最容易扣分的一条，对齐必须落在"同一实例"而不是"同一字符串"。

### 3.4 证据与来源绑定（`L22`、`L58`、`L63`、`L88`）

| 层级 | 字段 |
|-|-|
| 论文标识 | 独立 `source_id`（每篇一个，不复用） |
| 段落定位 | `paragraph_id`（= 组织方 JATS 段落 ID） |
| 原文片段 | 短引，逐字 |
| 证据强度 | 直接 / 间接 / 表格 / 图注 等（题面要求"标注证据强度"） |
| 章节或图表位置 | 有则记（本包无图，见 §2） |

**禁止**：自建页码冒充原 PDF 页（`L88`）。

### 3.5 查询（`L22`、`L86`）

- 至少 **3 个真实执行过的查询**（`L86`），不是伪代码。
- 每个查询要给：**结果子图** + **支撑证据** + **无法确定的关系**（`L22`）。

### 3.6 增量更新（`L22`，六方向之一，可选）

新论文加入时：保留既有节点与编号；说明**新增 / 合并 / 冲突**关系的处置方式；
导出可读的图谱文件。

> 六个方向（实体识别、实体对齐、关系抽取、来源绑定、图谱查询、增量更新）**选一个明确问题**
> 即可，不要求全做（`L22`、`L23`）。但 §2 的跨篇要求（两篇同一图谱、≥3 查询、记录不合并）
> 是输入修订里追加的，属于**必做**部分 `【推断：修订段用"；"列举了同一图谱、查询、合并记录三件事，
> 语气为强制】`。

## 4. 格式要求 —— 题面到底指定了什么

题面**没有**指定 RDF/Turtle/三元组这类具体序列化 `【事实：全文未出现 RDF、Turtle、SPARQL、三元组字样】`。
它指定的是一组**能力与字段**：

| 要求 | 出处 |
|-|-|
| 每个案例返回**一份结构化结果** | `L58` |
| 保留**输入标识**、**主结果**、**证据/来源定位**、**运行状态**、**不确定性** | `L58` |
| 结果须能**被查询**、能**导出可读的图谱文件** | `L22`、`L33` |
| `result.json` 含 **output_contract 全部字段 + `case_id`** | `L77` |
| 状态四态：**成功 / 部分完成 / 无法判断 / 拒答**，附原因与人工接管位置 | `L64` |
| 未报告、无法判断、材料冲突要**明确说明**，不能写成事实 | `L13`、`L63` |
| 关键结论要能**回到页码/段落/字段/图表定位** | `L12`、`L63` |

所以 `【推断，待 case.json 到手验证】`：

1. 序列化格式由参赛者自定，但必须 ①机器可读（下游能直接解析）、②字段齐全、
   ③每条节点/边可回原文、④有一份人能读的导出。
2. `output_contract` 的真实字段名**只在运行时 `/input/case.json` 里**，题面未列出——
   这是当前唯一硬缺口，Skill 必须**运行时读取 `case.json` 的 `output_contract` 再落盘**，
   而不是硬编码字段名。这一条会直接决定"结果完整性 5 分 / 结果可核验性 5 分"。
3. 因为评分是 `human_review_only`（`challenge.json` 的 `scoring.strategy`，
   `formula_summary`: *"No automated scoring; reviewers grade attempts manually."*），
   证据链的人可读性权重高于 schema 完备度。

## 5. 评分（`L31-41`）

满分 100，GitHub 公开链接另加 5（`L29`、`L41`）。

| 维度 | 分值 | 细项 |
|-|-|-|
| 实际效果 | 40 | 任务完成度 15；结果正确性 15；结果完整性 5；结果可核验性 5 |
| 使用增益 | 25 | 质量增益 15；效率增益 5；增益可验证性 5 |
| 创新增益 | 15 | 新增能力 5；方法改进 5；创新证据 5 |
| 可靠体验 | 10 | 调用与易用性 3；运行稳定性 4；异常处理 3 |
| 生态贡献 | 10 | 文档完整性 3；资源可复用性 4；分享推广价值 3 |

关键判据（原文）：

- 实际效果：是否**真的**把一批论文转成**带证据的节点与边**并交付**可查询**图谱；实体是否真实出现；
  关系类型与方向是否与原文一致；合并是否正确；节点与边能否回到具体位置和原文片段（`L33`）。
- 使用增益：**同输入对照**基础 Agent，图谱质量是否提升；是否减少逐篇摘录/人工比对/重复合并/查询返工；
  是否用同输入对照证明改善（`L34`）。**文字自述不能替代实际运行证据**（`L39`）。
- 创新增益：基础 Agent 或现有方案**不具备**的跨篇对齐/证据绑定/增量更新能力（`L35`）。
- 可靠体验：异常场景点名——文献缺失、PDF 无法解析、实体同名、关系证据冲突、查询无结果（`L36`）。
- 生态贡献：实体与关系类型定义、依赖、示例、适用范围、维护信息齐全；Skill/脚本/schema/题集/
  参考图谱/查询模板可复用（`L37`）。
- 白板（whiteboard）由组织方固定提供，是**对照结果**不是参赛者答案（`L25`）。
